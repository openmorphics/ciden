# 08 Frameworks Overview and Comparison

Purpose
- Compare widely used spiking and neuromorphic simulation frameworks with respect to model support, plasticity, performance (CPU/GPU), and event-driven capabilities.
- Clarify how the C‑IDEN training and SR readout pipeline interfaces with each framework, emphasizing training–inference decoupling and framework-agnostic intensity modeling.

Implementation anchors in sr_ciden
- Train continuous-time intensities via exact marked-TPP likelihood using augmented ODEs: see [`Python.nll_continuous()`](src/sr_ciden/losses.py:152), [`Python.odeint_augmented()`](src/sr_ciden/solvers.py:455), and solver wrapper [`Python.odeint_wrapper()`](src/sr_ciden/solvers.py:298).
- Latent neural ODE, stable generator, and jump updates: [`Python.LinearNonlinearODE()`](src/sr_ciden/dynamics.py:191), [`Python.StableMatrixParam()`](src/sr_ciden/dynamics.py:126), [`Python.JumpMLP()`](src/sr_ciden/dynamics.py:282).
- Inference-only SR readout (sampling): [`Python.sample_ogata()`](src/sr_ciden/readout.py:152), [`Python.sample_ogata_with_stats()`](src/sr_ciden/readout.py:242), [`Python.sample_bernoulli()`](src/sr_ciden/readout.py:183). PyTorch adapter: [`Python.CIDENContinuous.get_intensity_fn()`](src/sr_ciden/adapters/torch.py:191).

## 1. Conceptual roles: sr_ciden vs simulation frameworks

- sr_ciden
  - Purpose: learn a continuous-time conditional intensity λ(h(t), t) with rigorous likelihood, validation (time-rescaling), and inference-only spike sampling. Optimizes parameters of a latent ODE with differentiable jumps and a nonnegative intensity head (K marks).
  - Outputs for interop: an intensity function over time (and marks) for downstream simulators; optionally sampled spikes via SR readout.

- Simulation frameworks
  - Purpose: build and execute networked neuron/synapse models with explicit state evolution, event scheduling, plasticity rules, and hardware targets; often emphasize biophysical interpretability or simulator-scale performance.
  - Interop pattern: consume either
    - spikes generated by sr_ciden SR readout as inputs to a simulator network; or
    - rates/latencies derived from sr_ciden intensities for rate/latency interface nodes.

Training–inference decoupling
- Training stays in sr_ciden (PyTorch) using ODE-based likelihood. Simulation frameworks are primarily used for deployment, benchmarking, and hybrid pipelines, not for training the C‑IDEN intensity model.

## 2. Framework snapshots and interop notes

Below, “Interop with sr_ciden” sketches the primary bridge surfaces. Detailed templates are in 09 Integration Guides.

### 2.1 snnTorch (PyTorch-based)
- Focus and maturity
  - Educational and research-oriented SNN library on top of PyTorch; active ecosystem; convenient for surrogate-gradient training and GPU acceleration.
- Neuron models
  - LIF/ALIF variants, basic synaptic filters, multi-layer SNNs, custom cells.
- Plasticity
  - Surrogate gradient workflows, some local learning recipes via tutorials.
- Performance
  - GPU-friendly; benefits from PyTorch kernels.
- Event handling
  - Time-stepped with batched tensors; not event-driven in the simulator sense.
- Interop with sr_ciden
  - Direct PyTorch compatibility for using sr_ciden’s intensity in inference loops.
  - Option A: Use [`Python.CIDENContinuous.get_intensity_fn()`](src/sr_ciden/adapters/torch.py:191) to generate spikes via [`Python.sample_ogata()`](src/sr_ciden/readout.py:152) and feed them to snnTorch as inputs.
  - Option B: Convert intensities to per-step Bernoulli rates and feed spike tensors (discrete-time) produced by [`Python.SRReadoutTorch()`](src/sr_ciden/adapters/torch.py:260).

### 2.2 Brian2
- Focus and maturity
  - Flexible simulator with equation-based model definitions; strong for custom ODEs and research.
- Neuron models
  - Rich catalog; easy to define custom dynamics and synapses with state variables.
- Plasticity
  - Built-in STDP variants; user-defined plasticity via differential equations and event handlers.
- Performance
  - CPU-oriented with code generation; GPU via Brian2GeNN backend for acceleration.
- Event handling
  - Event-driven scheduling; supports threshold conditions and resets; robust spike timing.
- Interop with sr_ciden
  - Use SR spikes as inputs to Brian2 networks (event injection).
  - Alternative: Treat sr_ciden intensity as an external rate signal to drive PoissonGroup-like inputs or custom current injections; for hybrid models, align state-space and step sizes.

### 2.3 NEST
- Focus and maturity
  - Large-scale spiking network simulations; performance and stability emphasized.
- Neuron models
  - Catalog of IF and conductance-based models; extensible through NESTML.
- Plasticity
  - Standard STDP and synaptic models; structural plasticity extensions.
- Performance
  - Highly optimized CPU parallelism; distributed simulations.
- Event handling
  - Event-driven spikes; precise scheduling at scale.
- Interop with sr_ciden
  - Use SR-generated spike trains to stimulate NEST networks; or map intensities to Poisson generators for rate interfaces.
  - For closed-loop robotics/control, consider latency and synchronization between sr_ciden inference and NEST stepping.

### 2.4 Nengo
- Focus and maturity
  - High-level, function-oriented neural modeling (NEF), supports rate and spiking backends, and deployment targets.
- Neuron models
  - LIF/RectifiedLinear and others, emphasis on functional approximation.
- Plasticity
  - Learning rules including PES, BCM; integration with neuromorphic backends via Nengo Loihi.
- Performance
  - Depends on backend; Nengo Loihi targets Intel Loihi hardware.
- Event handling
  - Primarily time-stepped abstractions; spiking backends available.
- Interop with sr_ciden
  - Bridge via rate or latency interfaces: convert sr_ciden intensities to instantaneous rates or first-spike latencies for Nengo nodes/ensembles.

### 2.5 SpykeTorch
- Focus and maturity
  - Event-based SNN library on top of PyTorch with emphasis on time-to-first-spike, rank-order coding, and convolutional layers.
- Neuron models
  - Time-to-first-spike and convolutional SNN constructs.
- Plasticity
  - Unsupervised layers; rank-order and local learning mechanisms.
- Performance
  - GPU through PyTorch; tailored data structures for spike timing.
- Event handling
  - Discrete-time with sparse spike tensors.
- Interop with sr_ciden
  - Convert intensities to discrete-time spike tensors (Bernoulli/rank-order) using [`Python.sample_bernoulli()`](src/sr_ciden/readout.py:183) or a rank-order encoder (see 04).
  - Integrate as input layers or replacement of early sensing stages for event cameras.

## 3. Feature highlights by category

Neuron model support (indicative)
- snnTorch: LIF/ALIF, custom PyTorch cells.
- Brian2: equation-defined models; LIF, Izhikevich, QIF, conductance synapses.
- NEST: catalog of integrate-and-fire and conductance-based models; NESTML for custom.
- Nengo: LIF and rate models; functional approximation via NEF.
- SpykeTorch: time-to-first-spike, rank-order, convolutional SNN layers.

Plasticity
- snnTorch: surrogate gradient recipes; tutorials for STDP-like effects.
- Brian2: STDP variants and arbitrary rule specification.
- NEST: STDP, structural plasticity extensions.
- Nengo: PES, BCM; backend-dependent.
- SpykeTorch: unsupervised, rank-order mechanisms.

GPU/CPU and scale
- snnTorch/SpykeTorch: GPU via PyTorch; good for prototyping and mid-scale.
- Brian2: CPU codegen; GPU via Brian2GeNN for speedups.
- NEST: CPU and distributed scaling; strong for large spiking networks.
- Nengo: backend-dependent; Nengo Loihi for neuromorphic hardware.

Event-driven capabilities
- Strong event scheduling: Brian2, NEST.
- Time-stepped abstractions: snnTorch, Nengo core, SpykeTorch (with sparse spike tensors).

Interop considerations with sr_ciden
- If you need exact TPP semantics and precise timing, generate spikes with SR readout and feed as exogenous events.
- If a framework requires gridded inputs, convert intensities to Bernoulli spike tensors at a calibrated dt.
- Keep training in sr_ciden for intensity learning; use frameworks for downstream processing, closed-loop control, or hardware-aligned simulations.

--------------------------------------------------------------------------------

## 4. Choosing a stack

- Education and rapid PyTorch prototyping: snnTorch, SpykeTorch + sr_ciden intensity for inputs.
- Custom ODEs and synaptic state with event-driven precision: Brian2 + SR spikes.
- Large-scale network benchmarks: NEST + SR spikes or rate interfaces.
- Functional modeling and Loihi deployment: Nengo + rate/latency bridge from sr_ciden.
